## What is CWE-362?

**CWE-362** refers to the risk of race conditions, which happen when multiple threads or processes access a shared resource (like a variable or file) at the same time without proper synchronization. This can lead to unpredictable behavior, data corruption, or security vulnerabilities.

In Rust, race conditions are less common because the language enforces strict ownership rules. However, if you use shared mutable state (e.g., `Arc<Mutex<T>>`), improper synchronization can still lead to race conditions.

---

### Example of the Problem

Here’s an example of a race condition in Rust using threads and a shared counter:

```rust
use std::sync::Arc;
use std::thread;

fn main() {
    let counter = Arc::new(0); // Shared counter
    let mut handles = vec![];

    for _ in 0..10 {
        let counter = Arc::clone(&counter);
        let handle = thread::spawn(move || {
            // Unsafe mutation of the shared counter
            *Arc::get_mut(&mut counter).unwrap() += 1;
        });
        handles.push(handle);
    }

    for handle in handles {
        handle.join().unwrap();
    }

    println!("Final counter value: {}", counter);
}
```

Why This Is Problematic?

- The code tries to modify the shared counter (Arc) directly, which is not allowed in Rust's safe mode.
- If you bypass Rust's safety guarantees (e.g., using unsafe), multiple threads could modify the counter simultaneously, leading to incorrect results.
- Without proper synchronization, the final value of the counter might not be 10 as expected.

---

### Simple Solution

To fix this issue, we need to use proper synchronization tools like Mutex to ensure only one thread can modify the shared resource at a time. Here’s the corrected code:

```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0)); // Shared counter wrapped in a Mutex
    let mut handles = vec![];

    for _ in 0..10 {
        let counter = Arc::clone(&counter);
        let handle = thread::spawn(move || {
            // Lock the Mutex to safely modify the shared counter
            let mut num = counter.lock().unwrap();
            *num += 1;
        });
        handles.push(handle);
    }

    for handle in handles {
        handle.join().unwrap();
    }

    println!("Final counter value: {}", *counter.lock().unwrap());
}
```

Explanation of the Fix:

1. Use Mutex for Synchronization :
    - A Mutex ensures that only one thread can access the shared resource at a time.
    - When a thread locks the Mutex, other threads must wait until the lock is released.
2. Wrap the Shared Resource in Arc :
    - Arc (Atomic Reference Counted) allows multiple threads to share ownership of the resource safely.
    - Combined with Mutex, it ensures both thread safety and proper synchronization.
3. Avoid unsafe Code :
    - Rust’s ownership model prevents accidental misuse of shared resources. By using Mutex and Arc, we stay within safe Rust and avoid race conditions.
4. Test the Output :
    - With proper synchronization, the final counter value will always be 10, regardless of how the threads are scheduled.
