## What is CWE-908?

**CWE-908** refers to the risk of using uninitialized resources, such as variables, memory, or file handles, before they are properly initialized. This can lead to unpredictable behavior, crashes, or security vulnerabilities.

In languages like C or C++, uninitialized variables can contain garbage values, which may cause bugs or expose sensitive information. However, Rust’s strict compile-time checks ensure that all variables are initialized before use, making this issue virtually impossible in Safe Rust. That said, using `unsafe` code or interacting with external libraries can reintroduce this risk.

---

### Example of the Problem

Here’s an example of what using an uninitialized resource might look like if Rust allowed it (this code would not compile in Safe Rust):

```rust
fn main() {
    let x: i32; // Uninitialized variable

    // Attempt to use the uninitialized variable
    println!("Value of x: {}", x);
}
```

Why This Is Problematic?

- The variable x is declared but not initialized, meaning it has no defined value.
- In languages like C, using an uninitialized variable could result in undefined behavior, such as reading garbage values or causing crashes.
- In Rust, the compiler catches this error at compile time and prevents the program from building.

---

### Simple Solution

Rust’s strict initialization rules prevent the use of uninitialized resources by default. Here’s how Rust handles the same scenario safely:

```rust
fn main() {
    let x: i32 = 42; // Properly initialize the variable

    // Safely use the initialized variable
    println!("Value of x: {}", x);
}
```

Explanation of the Fix:

1. Mandatory Initialization :
    - Rust ensures that all variables must be initialized before they are used.
    - If you try to use a variable without initializing it, the compiler will throw an error.
2. Safe Abstractions :
    - Rust’s type system enforces strict rules about variable initialization, eliminating the risk of using uninitialized resources.
3. Avoid unsafe Code :
    - While Rust allows unsafe blocks for low-level operations, sticking to Safe Rust ensures that all resources are properly initialized.
