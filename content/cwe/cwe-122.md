## What is CWE-122?

**CWE-122** refers to the risk of heap-based buffer overflows, where data is written outside the bounds of a dynamically allocated memory buffer (e.g., memory allocated on the heap). This can lead to crashes, undefined behavior, or security vulnerabilities like code execution exploits.

In languages like C or C++, heap-based buffer overflows are common because developers manually manage memory allocation and deallocation. However, Rust’s strict memory safety guarantees make heap-based buffer overflows virtually impossible in Safe Rust. That said, using `unsafe` code or interacting with external libraries can reintroduce this risk.

---

### Example of the Problem

Here’s an example of what a heap-based buffer overflow might look like if Rust allowed it (this code would not compile in Safe Rust):

```rust
fn main() {
    let mut buffer = vec![0; 5]; // A dynamically allocated array on the heap
    let index = 10; // Out-of-bounds index

    // Attempt to write to an out-of-bounds index
    buffer[index] = 42;
    println!("Buffer: {:?}", buffer);
}
```

Why This Is Problematic?

- The code tries to write to index 10, but the vector only has indices 0 to 4.
- In languages like C, this would result in a heap-based buffer overflow, potentially corrupting memory or causing undefined behavior.
- In Rust, the compiler catches this error at compile time and prevents the program from building.

---

### Simple Solution

Rust’s strict memory safety guarantees prevent heap-based buffer overflows by default. Here’s how Rust handles the same scenario safely:

```rust
fn main() {
    let mut buffer = vec![0; 5]; // A dynamically allocated array on the heap
    let index = 10; // Out-of-bounds index

    // Safely access the vector using bounds checking
    if index < buffer.len() {
        buffer[index] = 42;
        println!("Buffer: {:?}", buffer);
    } else {
        println!("Error: Index {} is out of bounds!", index);
    }
}
```

Explanation of the Fix:

1. Bounds Checking :
    - Rust automatically checks indices at runtime to ensure they are within bounds.
    - If an index is out of bounds, Rust panics and stops the program, preventing undefined behavior.
2. Safe Abstractions :
    - Rust’s Vec<T> type provides a safe abstraction for working with dynamically allocated memory.
    - These abstractions eliminate the need for manual memory management, reducing the risk of buffer overflows.
3. Avoid unsafe Code :
    - While Rust allows unsafe blocks for low-level operations, sticking to Safe Rust ensures memory safety by default.
