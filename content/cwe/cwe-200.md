## What is CWE-200?

**CWE-200** refers to the risk of exposing sensitive information to unauthorized actors. This can happen when sensitive data (e.g., passwords, API keys, or personal information) is accidentally logged, printed, or transmitted insecurely. Attackers can exploit this exposure to gain unauthorized access or compromise systems.

In Rust, while the language does not inherently prevent developers from mishandling sensitive data, it provides tools and best practices to help mitigate this risk. Proper handling of sensitive information requires careful attention to logging, error messages, and data transmission.

---

### Example of the Problem

Here’s an example of what exposing sensitive information might look like in Rust:

```rust
fn main() {
    let username = "admin";
    let password = "supersecret"; // Sensitive information

    // Simulate logging user credentials for debugging
    println!("Debug: Username = {}, Password = {}", username, password);

    // Simulate sending credentials over an insecure channel
    send_credentials_over_http(username, password);
}

fn send_credentials_over_http(username: &str, password: &str) {
    println!("Sending credentials over HTTP: {} / {}", username, password);
}
```

Why This Is Problematic?

- The code logs sensitive information (password) to the console, which could be captured in logs or viewed by unauthorized users.
- The code sends sensitive information over an insecure HTTP connection, making it vulnerable to interception.
- Exposing sensitive data in logs or insecure channels can lead to data breaches or unauthorized access.

---

### Simple Solution

To fix this issue, we need to follow secure coding practices to protect sensitive information. Here’s the corrected code:

```rust
use std::env;

fn main() {
    let username = "admin";
    let password = env::var("USER_PASSWORD").unwrap_or_else(|_| "default_password".to_string()); // Load sensitive data securely

    // Avoid logging sensitive information
    println!("Debug: Username = {}", username);
    // Do NOT log the password

    // Send credentials over a secure channel (HTTPS)
    send_credentials_over_https(username, &password);
}

fn send_credentials_over_https(username: &str, password: &str) {
    // Simulate sending credentials over HTTPS
    println!("Sending credentials securely over HTTPS: {} / [REDACTED]", username);
}
```

Explanation of the Fix:
1. Avoid Logging Sensitive Data :
    - Never log sensitive information like passwords or API keys. In the corrected code, only the username is logged, and the password is omitted.
2. Load Sensitive Data Securely :
    - Use environment variables (env::var) to load sensitive data like passwords instead of hardcoding them in the source code.
    - This ensures sensitive data is not exposed in the codebase or version control.
3. Use Secure Channels :
    - Always transmit sensitive data over secure channels like HTTPS instead of insecure protocols like HTTP.
    - In the corrected code, the function send_credentials_over_https simulates secure transmission.
4. Redact Sensitive Information :
    - When debugging or displaying information, redact sensitive data (e.g., replace passwords with [REDACTED]).
